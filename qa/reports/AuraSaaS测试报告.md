## 4. 各模块详述

### 4.1 自动化测试与 CI（pytest 118 条）

- **覆盖范围**：工具执行、权限门控、工作流节点、API 接口、RAG 检索 5 类，共 118 条用例、7 个测试模块。
- **零 Key 离线回归**：通过 mock LLM 返回，实现无 DeepSeek API Key 环境下的全量回归，单次执行约 50s，免去 LLM 调用成本。
- **CI 接入**：接入 GitHub Actions，在 PR 阶段自动执行测试，避免回归遗漏。
- **执行命令**：`cd backend && python -m pytest app/tests/ -v`

### 4.2 RAG 检索评测（51 条评测集）

- **评测集**：构建 51 条业务查询，覆盖选址、客流、库存、营销等场景。
- **指标**：Top-5 Recall、MRR（平均倒数排名）。
- **对比**：关键词检索 vs 向量检索效果对比。
- **结果**：初版 Recall 仅 66.7%；定位到 **embedding 模型下载失败导致的向量化降级**及 **Chroma 持久化版本兼容问题**，推动修复后 Recall 提升至 **98%（50/51 命中）**，MRR 达 **83.86%**。

### 4.3 Agent 工作流测试

- 覆盖 LangGraph **11 个节点、21 个工具**的链路执行。
- 验证 **5 级权限门控**：不同权限角色可调用工具范围隔离有效。
- 覆盖节点执行、工具调用、异常分支等场景。

### 4.4 性能测试（Locust）

- **被测接口**：经营分析报告生成、库存查询等核心 API。
- **压测方式**：50 并发阶梯压测。
- **结果**：稳态 **QPS 47**、**P99 19ms**、未出现请求失败。
- **瓶颈定位**：发现 SQLite 高并发写锁导致吞吐下降，输出迁移 PostgreSQL 的性能数据依据与建议，推动团队完成数据库升级。

### 4.5 UI E2E 测试（Selenium 7 条）

针对前端（Vue 3）编写的端到端用例，覆盖核心业务链路：

| 编号 | 用例 | 断言点 | 结果 |
|---|---|---|---|
| TC-UI-01 | 注册 E2E | 填表提交 → 跳转看板 | ✅ |
| TC-UI-02 | 登录成功 | 离开登录页 + 看板元素出现 | ✅ |
| TC-UI-03 | 错误密码登录 | 停留登录页 + 错误文案 | ✅ |
| TC-UI-04 | 鉴权拦截 | 未登录访 `/app/dashboard` 重定向至 `/login` | ✅ |
| TC-UI-05 | 退出登录 | 点头像→退出→回登录页 | ✅ |
| TC-UI-06 | AI 分析冒烟 | 提问 → 用户消息出现在聊天区 | ✅ |
| TC-UI-07 | 表单校验 | 空表单提交被前端拦截 | ✅ |

> **非确定性处理**：AI 回答内容非确定，TC-UI-06 仅断言"用户消息出现在聊天区"，不断言具体回复文字，避免用例随机失败（flaky）。
> **选择器来源**：所有选择器均从前端源码（router / Login.vue / Register.vue / MainLayout.vue / AIAnalysis.vue）核对真实路由与元素，可稳定复现。
> **执行命令**：`pytest test_aura_ui.py -s -v`（需前后端均启动）

## 5. 发现的问题与定位

| # | 问题 | 定位方式 | 处置 |
|---|---|---|---|
